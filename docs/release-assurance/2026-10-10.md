## Candidate security review

Production has 45 authenticated public SECURITY DEFINER functions. The combined
candidate has 48, including governed role assignment and invitation context.
The advisor's generic execution warnings are not silently waived or cleared by
changing grants that would break the application.

Source review found older privileged functions with active-membership checks
that did not independently require native email verification. The candidate
adds direct `auth.uid()` and native identity-verification guards to every one
of the 48 functions, preserving signatures, grants and pinned search paths.
Migration replay enforces that exact count and rejects anonymous execution.
The SQL negative matrix includes an unconfirmed identity with an active admin
membership, cross-tenant access, role escalation, confidential reporting,

failed at runtime. A private, verified-identity, tenant-checked, bounded helper
repairs the security-invoker view. The old public helper remains service-only;
the fix adds no public RPC. Auditor and foreign-tenant financial-helper calls
are rejected.

Assigned roles appear persistently and combine permissions without a role switch.
Manager reporting lines are distinct from role grants. Founder administration
defaults to no employment record or employee seat; employment is an explicit choice.

[38063877145](https://github.com/langaludidi/LeaveCtrl/actions/runs/38063877145).

The suite uses native signup, delivered local email challenges, verification
links, password sign-in, actual application pages and real JWT requests. It
does not replace Auth, fake confirmed production identities or bypass role gates.
The matrix covers six roles, two browser engines and three widths. Additional
cases exercise booking/approval/cancellation/balance restoration, founder setup
with and without employment, and displayed invitation roles before acceptance
and after welcome. These run against disposable Supabase, not signed-in production.

Accessibility fixes darken muted text, label the audit filters and make scrollable
tables keyboard-focusable. Each role landing must have no serious or critical
axe violations and no horizontal document overflow. Axe checks do not replace
screen-reader or human usability acceptance. WebKit is not a physical Safari device.

## Operational controls and remaining gates

The independent database freshness checker is implemented and replay-tested,
but not activated in production. It records overdue GitHub schedules independently
of the GitHub scheduler and keeps failure evidence; it does not make GitHub cron
punctual. Alert destination and delivery verification remain open.

A private production-only Vercel Blob store and sensitive cron/encryption
configuration have been provisioned. They take effect on the next production
deployment. The recovery key is held outside Git with restricted filesystem
permissions and still needs owner-controlled secure escrow. Encrypted backup
execution and controlled recovery are not yet accepted.

Legal approval is recorded from the product owner. Automated access to the
public legal URLs is blocked by Cloudflare; approved publication is unverified.
The owner declined a Supabase upgrade. App-level breached-password checks are
prepared for signup and recovery, but native protection remains disabled and
direct Auth API requests bypass the application check. That residual needs an
explicit release disposition.

Release remains NO-GO pending exact-candidate acceptance, production rollout
and migration parity, authenticated production smoke and remaining human UAT,
monitoring/alert delivery, sustained backups, encrypted recovery, legal
publication, and the password-control disposition. PR #67 includes onboarding
PR #65; PR #66's GitHub-only watchdog overlaps the independent control and must
not be merged blindly alongside it.
