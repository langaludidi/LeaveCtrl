## Approval authorization negative tests

A real pending leave request was used only inside rollback-scoped transactions.

Verified:

- legitimate manager acting on a direct report: simulated decision returned **approved**
- employee attempting to approve own request: rejected with **self_approval_not_allowed**
- admin from a different organisation attempting the same privileged RPC: rejected with **not_authorised**
- post-test request state: remained **pending_approval**, with no decision persisted

This proves both the intended positive manager path and two critical negative paths at the database RPC boundary.

## Release gates still open

The following should remain open until separately evidenced:

1. Vercel production deployment catches up to current `main`.
2. Duplicate Vercel Git project is disconnected or removed.
3. Supabase leaked-password protection is enabled/verified in Auth production settings.
4. Password recovery is completed through actual password update and subsequent sign-in.
5. HR/Admin mutation-path coverage should be extended beyond the tested remuneration boundary where practical.
6. Remaining leave/TOIL edge cases (including withdrawal/decline variants) receive targeted proof.
7. CSV onboarding/import failure and rollback behaviour receives proof.
8. Invitation/notification delivery and privacy matrix receives full evidence.
9. Responsive/accessibility browser regression receives controlled UAT evidence.
10. Backup/restore capability receives explicit proof.
